# 数据追踪平台 · 产品文档（PRD）

版本：v1.0 ｜ 日期：2026-10-16 ｜ 状态：待评审

---

## 1. 背景与目标

团队在投研中依赖两类高频另类数据判断资金面与产业景气度：

1. **ETF 份额变化**——观察资金申赎动向（如沪深300 ETF 单日 +45 亿份 = 大额申购信号）；
2. **大宗商品价格与库存**——观察产业链景气度（如电解铜库存连续下降 = 供给收紧信号）。

这类数据分散在交易所、行业网站等多个公开渠道，手工整理费时且无法沉淀历史。参考同类产品（见附录 B），我们要建一个**自动采集、统一查看**的内网数据追踪平台。

**产品目标**：团队打开一个内网网址，30 秒内看清"今天什么数据异动了、为什么值得注意"，并可对任意品种做历史回溯与跨品种对比。

## 2. 目标用户与场景

**用户**：内部投研小团队（3-8 人），无需注册登录，内网直接访问。

**核心场景**：

| 场景 | 描述 | 频率 |
|------|------|------|
| 每日速览 | 收盘后打开总览页，扫"今日异动"榜单，30 秒定位重点 | 每交易日 1-N 次 |
| 品种深查 | 点进某数据源，看成分品种卡片与历史曲线，判断趋势 | 按需 |
| 跨品种对比 | 在详情页叠加其他品种（如铜库存 vs ETF 份额），寻找共振线索 | 按需 |
| 数据可信确认 | 通过"数据截至日期 + 抓取状态"确认数据新鲜可靠 | 顺手 |

## 3. 范围

### 3.1 v1 包含

- **三个页面**：总览首页（异动优先）、数据源详情页（卡片行 + 趋势图）、详情页内对比能力（对比 chips + 归一化开关 + 时间范围切换）
- **三个首批数据源**：沪深300 ETF 份额（5 只成分基金）、煤炭价格、电解铜库存——跑通"采集→存储→展示"全链路
- **自动采集**：每交易日收盘后自动运行，含历史回补命令
- **数据质量展示**：数据实际日期标注（T+1）、各源抓取状态

### 3.2 v1 明确不做（架构预留，不做实现）

- 异动提醒推送（邮件/IM）——架构上保留 webhook 通道
- 导出 CSV / 图片、团队标注评论
- 独立对比页（对比能力收敛在详情页内）
- 用户体系与权限
- 盘中实时刷新

## 4. 信息查看设计（产品核心）

### 4.1 全局框架

深色左侧导航（沿用参考图）：顶部平台名，下方按分组列出数据源——「指数 ETF」「大宗商品」，首项为「📊 总览」。主区域浅色底。全站红涨绿跌（A 股习惯）。

### 4.2 总览首页（异动优先）

自上而下：

1. **页头**：「总览」+ 数据截至日期徽章 + 抓取状态（全部成功 / N 个数据源异常，异常红色可点）
2. **今日异动榜**（第一屏核心）：跨全部数据源扫描，表格列 = 数据源｜最新值｜变化（绝对值 + 百分比，红涨绿跌）｜5 日迷你趋势；按 |变化幅度| 降序，超过阈值才入榜；每行可点击跳转到对应详情页
3. **分组速览**：每个数据源一张小卡（名称、最新合计值、今日变化），点卡片进详情

### 4.3 数据源详情页（参考图样式）

以"沪深300 ETF"为例：

1. **页头横幅**：数据源名 + 徽章（成分数 · 交易日数）
2. **成分卡片行**：每个成分品种一张卡（如 510300：名称、代码、最新份额、日变化绝对值与百分比、红涨绿跌），选中态高亮
3. **趋势图**：多线折线图（每成分一条线，颜色区分），图例可开关，悬浮 tooltip 显示当日各线数值，支持 dataZoom 缩放
4. **对比 chips**：图上方一排 chips——当前品种各序列 + 「+ 添加对比」从其他数据源选序列加入；开启「归一化」后所有线以区间首日为基线 100 重绘
5. **时间范围切换**：1月 / 3月 / 6月 / 1年 / 全部
6. **数据日期标注**：图表角落标注每条序列的实际数据日期（ETF 份额 T+1）

### 4.4 交互原则

- 总览页任何数字块可点击下钻；详情页任何曲线可被其他品种叠加
- 异动阈值、成分品种、卡片字段全部由数据源注册表配置驱动（见设计文档）
- 空状态明确：新数据源无历史时显示"数据累积中（自 X 日起）"，不显示空图表

## 5. 数据源规划

### 5.1 首批（v1，跑通链路）

| 数据源 | 分组 | 内容 | 频率 | 采集方式 |
|--------|------|------|------|----------|
| 沪深300 ETF 份额 | 指数 ETF | 华泰柏瑞510300、易方达510310、中金510320、华夏510330、工银510350 的日份额 | 日频 | akshare（上交所接口，T+1） |

### 5.2 扩展路线（第二批/第三批，均为配置+新增 fetcher，不改前端）

| 批次 | 数据源 | 说明 |
|------|--------|------|
| 二 | 中证500 ETF 份额 | 同沪深300 模式 |
| 二 | 融资融券余额 | 全量历史现成 |
| 二 | 电解铝/氧化铝价格与库存、铝锭库存、电解铜价格 | akshare 现成 |

| 三 | 长江来水/三峡水位 | 难度最高（JS 渲染），放最后 |

## 6. 非功能需求

| 维度 | 要求 |
|------|------|
| 部署 | 内网单机（Linux VM），一个 systemd 服务 + 一个 timer，团队浏览器直接访问 |
| 性能 | 任意页面 3 秒内加载完成（数据量极小：年约十几万行） |
| 可靠性 | 单源采集失败不影响其他源与看板；停机错过调度自动补跑；采集异常推送 webhook 告警 |
| 数据质量 | 页面标注数据实际日期；静默失败（抓到 0 行/旧数据）必须被检测并告警 |
| 历史深度 | **能回溯的源尽可能回补**（如上交所 ETF 份额可回溯至 2015 年，约 11 年）；**接口只提供短窗口的源（如东财库存近 60 交易日）从上线日起每日累积**，以攒够 5-10 年为目标——这是长期验收标准，不阻塞上线 |
| 可维护性 | 新增数据源半天内完成（写 fetcher + 加配置），前端零改动 |
| 备份 | 每日采集成功后自动单文件备份，保留 30 天 |

## 7. 成功标准（v1 验收）

1. 团队成员浏览器打开 `http://内网IP:8000` 即可用，无需任何安装登录；
2. 每交易日收盘后数据自动更新，次日早上看到的是当日收盘数据（含 T+1 标注）；
3. 总览页能一眼看到当日跨源异动，异动行可下钻到详情页；
4. 沪深300 详情页呈现 5 只成分基金卡片行 + 份额历史曲线，可叠加煤炭价格并归一化对比；
5. 人为杀掉采集进程/断网重试后，数据不重不漏（幂等），异常有告警；
6. 新增一个"中证500 ETF 份额"数据源：只写 fetcher + 配置，不改任何前端代码，半天内上线。

## 8. 里程碑

| 阶段 | 内容 | 验收 |
|------|------|------|
| M1 数据管道 | 3 个 fetcher + 建库 + 历史回补 + systemd 部署 + 告警 | 数据入库可查询，重跑幂等，异常告警可达 |
| M2 看板核心 | 详情页（卡片+曲线+时间范围）+ 总览页（异动榜+速览） | 成功标准 1-3 |
| M3 对比与质量 | 对比 chips + 归一化 + 数据日期标注 + 抓取状态条 | 成功标准 4-6 |

参考工作量：1.5-2.5 人周（AI 辅助开发可显著压缩）。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| akshare 接口失效/字段变更 | 数据断更 | 固定版本起步；fetcher 样本 fixture 测试；告警快速发现；关键源留直连官方 API fallback |
| 库存接口只保留近 60 交易日 | 历史断层 | v1 上线即开始每日累积；接受初始历史有限并在 UI 标注 |
| 爬虫源（SCFI/动力煤/水文）反爬或改版 | 第三批延期 | 放最后批次；失败降级显示"最后成功日期"，不阻塞其他源 |
| 单机单点故障 | 服务中断 | systemd 自动拉起 + 每日单文件备份，重建成本低（一条命令回补全量历史） |
| 数据口径变化（单位/统计方式） | 曲线跳变 | observations 保留 raw_json 原始返回；异动阈值可按源配置 |

## 附录 A · 术语

- **份额（亿份）**：ETF 基金份额，变化反映申赎方向
- **T+1**：上交所份额数据次日公布，看板须标注实际日期
- **归一化**：各序列以区间首日为 100 重绘，消除量纲便于对比
- **异动**：环比变化幅度超过该数据源配置阈值
